## Задача

Сделать шейдерную оптимизацию пунктов **1–4**. Пункт 5 (запекание карты)
исключён пользователем. Цель — сократить число шейдерных программ и время
холодной линковки на VK/mobile, не потеряв качество картинки на high.

1. **Кэш и удержание прогретого** (без потери качества):
   - не освобождать прогретые материалы/шаблоны до конца матча;
   - `navigator.storage.persist()` для shader cache;
   - «первый запуск: подготовка графики» с прогрессом.
2. **Меньше вариантов без изменения вида:**
   - один источник правды для окружения: прогревочный вьюпорт и матч должны
     видеть **одно и то же** окружение/качество;
   - греть только выбранный класс/скин и тех, кто реально в комнате (проверить,
     что сейчас греется);
   - убрать реально неиспользуемые material features — только после A/B.
3. **Дешёвый radiance на low/VK** — только вместе с пунктом 2 (единое
   окружение), high не трогать. Если выигрыша нет — откатить.
4. **Low/VK-упрощения** (high не трогаем): `cull_back` для пола/плазы/травы/void
   в фабриках `arena_kit.gd` + двух материалах `Main.tscn`; убрать `rim`
   вместе с `_warm_rim_material`; свести дубли `StandardMaterial3D`.

## Что уже пробовали и откатили (не повторять)

- Убирали Sky / `reflection = DISABLED` / `ambient = COLOR` в рантайме и в
  сцене: **медленнее не стало, программ больше** (187 → 203–205), потому что
  прогрев и матч видят разное окружение и добавляются новые варианты. Даже без
  Sky остаётся 61 программа с `USE_RADIANCE_MAP`.
- `cull_disabled → cull_back` только в `game.gd`: **+1 вариант на материал**
  (203 против 187). Правильно — в `arena_kit.gd` и `Main.tscn`.
- Снимали `rim` только в `game.gd`: бессмысленно, `warmup_flow.gd:582`
  специально греет этот вариант. Убирать в обоих местах.
- `alpha_scissor`: неиспользуемых вариантов нет, только листва кустов.
- Кастомные `shaders/*` (`cloud_wall`, `fog_of_war`, `soft_ground_glow`) —
  `unshaded`, по одной программе; не трогать.

## Почему дубли (главная гипотеза пункта 1)

`warmup_flow.gd` инстансит `Main.tscn` без `game.gd` в своём SubViewport
(`own_world_3d = true`), затем освобождает `_main` (≈400, 820, 869), а
`game.gd:_warm_battle_world` освобождает модели. Материалы теряют последнюю
ссылку и линкуются заново в матче. Решение — держать прогретые инстансы
живыми (вне фрустума) до конца матча; это `game.gd` + `warmup_flow.gd`,
обязательно A/B и замер VRAM (мобильный two-pass бюджет 320 МБ).

## Ловушки

- Любая правка «только для матча» удваивает варианты: `warmup_flow.gd`
  прогревает сцену без `game.gd`. Менять в источнике (`arena_kit.gd`,
  `Main.tscn`, `warmup_flow.gd`), а не в `game.gd`.
- `warmup_flow.gd` решает «один/два прохода» по VRAM (порог 320 МБ) — набор
  материалов плавает, поэтому программы ±10 %.
- Мобильный keeper сейчас удерживает только аудио; тяжёлое удержание на
  two-pass запрещено (был FAIL 338.7 > 320.2 МБ).
- `tools/vk_perf_diag.js:220` отбрасывает кадры >2 с — фриз виден только в
  `longTasks`, не в `frameP95Ms`.

## Как мерить

- `?perf=1` на реальном VK/Chrome, панель `[VKPERF]` и
  `window.__vkperfReport()`: `SH links/seconds`, unique programs, worst link,
  long tasks, FPS/p95.
- `tools/vk_perf_cdp.mjs` — CDP-прогон с перехватом `compileShader` /
  `getProgramParameter(LINK_STATUS)`.
- Godot-пробы: `WarmupProbe` (844 two-pass и 1440), `BattleStartE2EProbe`,
  `FirstClashProbe`, `PerfBattleProbe`.
- Скриншоты high/low до/после — обязательны для пунктов 2–4.

## Критерии приёмки

- Число программ и/или время холодной линковки падает **больше шума** (≥15 %)
  на 2–3 прогонах; иначе правка откатывается.
- High-картинка не меняется (скриншоты), low/VK — не хуже «заметно».
- `WarmupProbe` 844: pass2 ≤ pass1 ≤ 320 МБ; 1440 peak ~390 МБ.
- `BattleStartE2EProbe` mobile: live 0–5 с max <33 мс.
- `HpDesyncProbe`, `FogProbe`, `NameTagProbe`, `ScoreboardProbe`,
  `ResultsProbe` — 0 FAIL; `go test`/`go vet` чисто.
