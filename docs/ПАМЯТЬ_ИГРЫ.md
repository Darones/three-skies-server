- **Фикс «капсул» в вебе (18.11.2026):** `scripts/hero.gd` и `scripts/remote_player.gd` искали модель через `DirAccess` по `*.tscn`. В экспортированном PCK текстовые сцены переименованы (`character.scn` + `character.tscn.remap`), скан ничего не находил → включалась капсула. Теперь грузится явный путь `res://art/generated/<class>/character.tscn` (Godot сам разрешает remap), а скан оставлен только как запасной вариант с учётом `.scn`/`.remap`.
- VK Bridge: `tools/vk-bridge.min.js` (3.0.2), вызывается `VKWebAppInit`; в HTML вставлен перед `index.js`.
- При экспорте PCK переименовывается в `index_<дата>.pck`, чтобы браузер/телефон не брал старый из кэша.
- Экспорт веба: `tools/web_export.py` (сам переключает Forward+ → Compatibility, экспортирует, делает cache-bust и вставляет VK Bridge).
- Предпросмотр A56: `run_phone_preview.bat` → `--device=a56`; для веба `?mobile=1`.
- После обновления веба нужно обновить ветку `gh-pages` (отдельный worktree) и дождаться Pages build.

## Сервер

- API: https://three-skies-server.relaxdev.ru
- WebSocket: wss://three-skies-server.relaxdev.ru/ws
- Health: https://three-skies-server.relaxdev.ru/health
- Правила: https://three-skies-server.relaxdev.ru/rules (`bot_fill_seconds`).
- **Матчмейкинг (18.11.2026):** комнату с ботами теперь запускает таймер **30 секунд после последнего вошедшего**, а не после первого. Таймер перезапускается на каждом входе (`server/ws.go`, `joinMatchmaking`). Раньше при задержке входа больше 15 секунд каждый игрок получал отдельную комнату с ботами — это воспроизвелось пробой: входы 0 с и 8 с попали в room 14, вход на 16-й секунде — в room 15. Клиентский отсчёт в `loading_screen.gd` синхронизирован (30 с).
- CORS включён для веба (GitHub Pages, локальные тесты).
- Деплой: RelaxDev Docker автоматически из GitHub `main`.
- База: PostgreSQL, health показывает состояние БД.
