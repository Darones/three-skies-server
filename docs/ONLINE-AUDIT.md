# Аудит онлайна «Небесные осколки»

Дата: 2026-11-20. Проверено на локальном сервере (`127.0.0.1:8090`) двумя
клиентами: хост `Игрок 7038` (Свет) и гость `Игрок 5557` (Тьма).

## 1. Как устроено сейчас

```
клиент A (хост)                         Go-сервер                         клиент B (гость)
────────────────                        ─────────                         ────────────────
сам двигает своего героя   ──state──►   хранит позицию/HP людей   ◄─state── сам двигает своего героя
сам симулирует ВСЕХ ботов  ──bot_states► хранит копию HP ботов     ─bot_states► рисует ботов по снапшотам
сам считает урон по ботам  ──attack_intent► проверяет дальность/КД  ──damage──► применяет урон
сам спавнит Оболочку/осколок            считает только счёт осколков            сам спавнит Оболочку/осколок
```

Ключевая особенность: **боты и объективные объекты (Оболочка, осколок)
симулируются на клиенте-хосте, а не на сервере.** Сервер владеет только HP
людей, счётом осколков, смертями/респавнами и проверкой атак.

## 2. Кто чем владеет

| Данные | Владелец | Комментарий |
|---|---|---|
| Позиция своего героя | клиент | сервер принимает и рассылает |
| HP людей | сервер | подтверждается `sync` и `damage` |
| HP ботов | **хост-клиент** | сервер только хранит копию |
| Урон по людям | сервер | клиент шлёт `attack_intent` |
| Урон по ботам | **хост-клиент** + сервер | гость шлёт intent, хост применяет |
| КД атак | сервер | по имени скилла |
| Смерть/респавн людей | сервер | `death`/`respawn` |
| Оболочка (HP, позиция, смерть) | **каждый клиент отдельно** | не синхронизирована |
| Осколок (позиция, носильщик) | **каждый клиент отдельно** | не синхронизирован |
| Счёт осколков | сервер | клиент шлёт `match_event` |
| Конец матча | сервер | исправлено, раньше решал клиент |

## 3. Найденные баги (с доказательствами)

### 3.1 HP регена не доходил до других игроков
Сервер применял реген в `updateState`, но `sync` отправлял **только
владельцу**. Другие видели HP только по событиям `damage`/`heal`, поэтому
на своём экране HP рос, а у противника стоял старый.

Лог гостя:
```
[HP] L:2 hp=97 sync=145
[HP] L:2 hp=97 sync=97
```
Исправлено: HP/max_hp/alive добавлены в каждый `state`-пакет (12 Гц), клиент
применяет их к удалённым игрокам и чинит пропущенный респавн.

### 3.2 Миникарта гостя не показывала союзников
`minimap.gd` перебирал только `game.heroes`. У хоста там боты, у гостя боты
лежат в `game.remote_players`. Поэтому у гостя исчезали союзники и не
рисовался второй игрок.

Исправлено: миникарта рисует и `remote_players` (союзники зелёные, враги
красные).

### 3.3 HP ботов «возвращается» после удара
Гость бьёт бота, сервер подтверждает урон:
```
[HIT] remote id=-2 amount=53 skill=auto source=0
[DMG] source=2 target=-2 amount=44 skill=auto
```
Но следующий снапшот хоста поднимает HP:
```
[BOTHP] id=-2 snapshot=800 current=754
[BOTHP] id=-2 snapshot=783 current=671
```
Причины: хост-клиент владеет HP ботов, и его реген/хил феи применяется
поверх урона гостя. Это не рассинхрон связи, а **хост-авторитетность ботов**:
гость видит ровно то, что насчитал хост. Плюс урон сервера (44) ниже
локального ролла клиента (53), потому что сервер считает по базовому
`attackDamage`, без крита/бафов.

Что делать: сервер должен считать урон по боту и хранить HP бота, а хост —
только присылать намерения/позиции. Либо, как минимум, передавать в
`attack_intent` фактический урон и не принимать рост HP бота от хоста в
течение N мс после подтверждённого урона.

### 3.4 AoE-ульты бьют только одну цель
Лог:
```
attack_denied target=-2 skill=fear_ult reason=cooldown
```
Клиент на каждый таргет шлёт отдельный `attack_intent` с одним и тем же
скиллом. Сервер на первом таргете ставит КД 15 с и отклоняет остальные цели
того же каста.

Что делать: добавить `cast_id` (один на каст) и разрешать несколько целей
с одним `cast_id`, либо слать один intent со списком целей.

### 3.5 Оболочка и осколок не синхронизированы
Каждый клиент спавнит свою Оболочку и свой осколок. HP Оболочки, её смерть,
позиция осколка и носильщик у хоста и гостя разные. Сервер получает только
события `shell_destroyed` и `shard_delivered`, но не состояние объектов.

Это отдельный слой, который нужно либо делать хост-авторитетным
(`shell_state`/`crystal_state` 12 Гц + интенты урона по Оболочке), либо
переносить на сервер.

### 3.6 Клиент завершал матч сам
Было исправлено ранее: локальный таймер и локальный счёт осколков вызывали
`end_match`. Теперь в сети завершает только сервер (`match_finished`), счёт
берётся с сервера, причина показывается на экране результатов.

### 3.7 Тест с телефона по LAN не запускается
Godot Web требует Secure Context. `http://192.168.1.102:8088` — не secure,
игра показывает «Отсутствуют следующие функции… используйте HTTPS».
Для телефона нужен HTTPS (локальный сертификат/туннель) либо тест на
`localhost`.

## 4. Как должно быть (целевая схема)

1. **Сервер — единственный владелец игровых фактов**: HP людей и ботов,
   урон, смерть, респавн, КД, счёт, Оболочка, осколок, носильщик.
2. **Клиент** присылает только ввод и намерения:
   - `move` (позиция/поворот, 12–15 Гц);
   - `attack_intent {target, skill, cast_id}`;
   - `use_ability {skill, cast_id, target/direction}`;
   - `pickup/deliver` — намерение, сервер проверяет расстояние.
3. **Сервер** валидирует (существование, команда, дальность, КД, живость),
   считает урон, применяет и рассылает **снапшот**:
   - люди: позиция, HP, max_hp, alive, анимация;
   - боты: позиция, HP, alive, анимация;
   - Оболочка: alive, hp, позиция, фаза;
   - осколок: состояние, позиция, носильщик;
   - счёт, таймер, фаза матча.
4. **Клиент** интерполирует удалённые сущности, предсказывает только своего
   героя и корректируется сервером. HP и смерти — **никогда** не по локальному
   решению клиента.
5. **Позднее подключение**: при входе сервер отдаёт полный снапшот, а не
   ждёт следующего события.
6. **Тест**: два клиента (хост/гость), задержка 100–200 мс, потеря 5–10%,
   смерть/респавн, Оболочка, осколок, конец матча. Проверять **оба экрана**,
   а не только хост.

## 5. План миграции (по шагам)

1. **Снапшоты людей** — уже сделано: HP в `state` 12 Гц.
2. **Урон** — передавать фактический урон в `attack_intent`, сервер
   клампит по `attackDamage * 2.5`; убрать разницу 53 vs 44.
3. **AoE** — `cast_id` на каст, сервер принимает все цели одного каста.
4. **Боты** — сервер считает урон и HP; хост присылает только позиции и
   намерения атак. Убрать «HP бота растёт обратно».
5. **Оболочка/осколок** — `shell_state`/`crystal_state` от хоста или сервера,
   урон по Оболочке — интентом.
6. **Тест-матрица** — два клиента, оба экрана, логи `[HP]`, `[HIT]`, `[DMG]`,
   `[BOTHP]`, `attack_denied`.

## 6. Что уже исправлено в этой итерации

- HP людей в каждом `state`-пакете и применение на клиенте.
- Респавн из `state`, если пакет смерти/респавна потерялся.
- Миникарта: `remote_players` (союзники и второй игрок).
- Конец сетевого матча — только сервер, счёт — только серверный.
- Реген базы ×2 вместо ×6 (60 HP/с делали игрока бессмертным).
- Ограничение клиентского `stats` (не больше 300 HP/с).
- HP ботов: сервер принимает HP хоста в обе стороны.
- Урон ботов по хосту идёт через `attack_intent`.
- Отладочные логи `[HP]`, `[HIT]`, `[DMG]`, `[BOTHP]`, `[SHELL]` при
  `?profile=1` — чтобы больше не гадать.

## 7. Итерация 21.11: серверный HP ботов и Оболочки

Сделано:
- **HP ботов принадлежит серверу.** Хост присылает только позицию, поворот и
  анимацию; HP/max_hp в `bot_states` игнорируются. Урон по ботам идёт через
  `attack_intent` / `bot_damage`, лечение — через `heal` с отрицательной
  целью, реген считает сервер. Сервер рассылает HP и хосту, и гостю.
- **HP и состояние Оболочки принадлежит серверу.** Хост присылает
  `shell_state` (позиция/фаза/таймер), HP не присылает. Урон по Оболочке —
  `shell_attack`; сервер применяет, рассылает `shell_state` и
  `match_event: shell_destroyed`. Гость не спавнит свою Оболочку, а рисует
  серверную.
- **Протокол 2.** Новый клиент с новым сервером использует серверный HP; со
  старым сервером (протокол 0) работает по-старому. Это защищает от
  смешанной версии при поэтапном деплое.
- Локальный тест: `[DMG] source=-4 target=-2 amount=32` → `B:-2 938/1000`,
  `B:-4 945/1050`; HP меняется ровно на подтверждённый урон, снапшоты хоста
  его не откатывают.
- Серверный тест `TestShellStateAndDamageAreServerOwned` проходит.

Осталось:
- **Осколок** (позиция, носильщик) всё ещё клиентский; счёт доставок —
  серверный. Это следующий слой.
- Атаки Оболочки по игрокам (PvE) остаются локальными на хосте.
- AI/движение ботов остаются на хосте (доверенный симулятор), сервер владеет
  их HP/уроном/смертью/регеном.

Тесты нового сервера (21.11, после рестарта ПК):
- `go test ./...` — все тесты проходят.
- `TestWebSocketBotSyncAndServerValidation` двумя WebSocket-клиентами:
  - welcome отдаёт `protocol: 2`;
  - урон гостя по боту применяется сервером;
  - снапшот хоста с полным HP **не поднимает** серверный HP;
  - лечение бота хостом применяется сервером;
  - `shell_state` создаёт Оболочку на 1000 HP;
  - урон по Оболочке применяется сервером, снапшот хоста с HP 100
    игнорируется;
  - смерть Оболочки и `match_event: shell_destroyed` приходят от сервера;
  - матч завершается серверным счётом.
- Локальный браузерный прогон (до рестарта): `B:-2 938/1000`,
  `B:-4 945/1050` — HP ботов меняется ровно на подтверждённый урон.
