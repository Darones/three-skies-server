# Аудит онлайна «Небесные осколки»

Дата: 2026-11-20. Проверено на локальном сервере (`127.0.0.1:8090`) двумя
клиентами: хост `Игрок 7038` (Свет) и гость `Игрок 5557` (Тьма).

## 1. Как устроено сейчас

```
клиент A (хост)                         Go-сервер                         клиент B (гость)
────────────────                        ─────────                         ────────────────
сам двигает своего героя   ──state──►   хранит позицию/HP людей   ◄─state── сам двигает своего героя
сам симулирует ВСЕХ ботов  ──bot_states► хранит копию HP ботов     ─bot_states► рисует ботов по снапшотам
сам считает урон по ботам  ──attack_intent► проверяет дальность/КД  ──damage──► применяет урон
сам спавнит Оболочку/осколок            считает только счёт осколков            сам спавнит Оболочку/осколок
```

Ключевая особенность: **боты и объективные объекты (Оболочка, осколок)
симулируются на клиенте-хосте, а не на сервере.** Сервер владеет только HP
людей, счётом осколков, смертями/респавнами и проверкой атак.

## 2. Кто чем владеет

| Данные | Владелец | Комментарий |
|---|---|---|
| Позиция своего героя | клиент | сервер принимает и рассылает |
| HP людей | сервер | подтверждается `sync` и `damage` |
| HP ботов | **хост-клиент** | сервер только хранит копию |
| Урон по людям | сервер | клиент шлёт `attack_intent` |
| Урон по ботам | **хост-клиент** + сервер | гость шлёт intent, хост применяет |
| КД атак | сервер | по имени скилла |
| Смерть/респавн людей | сервер | `death`/`respawn` |
| Оболочка (HP, позиция, смерть) | **каждый клиент отдельно** | не синхронизирована |
| Осколок (позиция, носильщик) | **каждый клиент отдельно** | не синхронизирован |
| Счёт осколков | сервер | клиент шлёт `match_event` |
| Конец матча | сервер | исправлено, раньше решал клиент |

## 3. Найденные баги (с доказательствами)

### 3.1 HP регена не доходил до других игроков
Сервер применял реген в `updateState`, но `sync` отправлял **только
владельцу**. Другие видели HP только по событиям `damage`/`heal`, поэтому
на своём экране HP рос, а у противника стоял старый.

Лог гостя:
```
[HP] L:2 hp=97 sync=145
[HP] L:2 hp=97 sync=97
```
Исправлено: HP/max_hp/alive добавлены в каждый `state`-пакет (12 Гц), клиент
применяет их к удалённым игрокам и чинит пропущенный респавн.

### 3.2 Миникарта гостя не показывала союзников
`minimap.gd` перебирал только `game.heroes`. У хоста там боты, у гостя боты
лежат в `game.remote_players`. Поэтому у гостя исчезали союзники и не
рисовался второй игрок.

Исправлено: миникарта рисует и `remote_players` (союзники зелёные, враги
красные).

### 3.3 HP ботов «возвращается» после удара
Гость бьёт бота, сервер подтверждает урон:
```
[HIT] remote id=-2 amount=53 skill=auto source=0
[DMG] source=2 target=-2 amount=44 skill=auto
```
Но следующий снапшот хоста поднимает HP:
```
[BOTHP] id=-2 snapshot=800 current=754
[BOTHP] id=-2 snapshot=783 current=671
```
Причины: хост-клиент владеет HP ботов, и его реген/хил феи применяется
поверх урона гостя. Это не рассинхрон связи, а **хост-авторитетность ботов**:
гость видит ровно то, что насчитал хост. Плюс урон сервера (44) ниже
локального ролла клиента (53), потому что сервер считает по базовому
`attackDamage`, без крита/бафов.

Что делать: сервер должен считать урон по боту и хранить HP бота, а хост —
только присылать намерения/позиции. Либо, как минимум, передавать в
`attack_intent` фактический урон и не принимать рост HP бота от хоста в
течение N мс после подтверждённого урона.

### 3.4 AoE-ульты бьют только одну цель
Лог:
```
attack_denied target=-2 skill=fear_ult reason=cooldown
```
Клиент на каждый таргет шлёт отдельный `attack_intent` с одним и тем же
скиллом. Сервер на первом таргете ставит КД 15 с и отклоняет остальные цели
того же каста.

Что делать: добавить `cast_id` (один на каст) и разрешать несколько целей
с одним `cast_id`, либо слать один intent со списком целей.

### 3.5 Оболочка и осколок не синхронизированы
Каждый клиент спавнит свою Оболочку и свой осколок. HP Оболочки, её смерть,
позиция осколка и носильщик у хоста и гостя разные. Сервер получает только
события `shell_destroyed` и `shard_delivered`, но не состояние объектов.

Это отдельный слой, который нужно либо делать хост-авторитетным
(`shell_state`/`crystal_state` 12 Гц + интенты урона по Оболочке), либо
переносить на сервер.

### 3.6 Клиент завершал матч сам
Было исправлено ранее: локальный таймер и локальный счёт осколков вызывали
`end_match`. Теперь в сети завершает только сервер (`match_finished`), счёт
берётся с сервера, причина показывается на экране результатов.

### 3.7 Тест с телефона по LAN не запускается
Godot Web требует Secure Context. `http://192.168.1.102:8088` — не secure,
игра показывает «Отсутствуют следующие функции… используйте HTTPS».
Для телефона нужен HTTPS (локальный сертификат/туннель) либо тест на
`localhost`.

## 4. Как должно быть (целевая схема)

1. **Сервер — единственный владелец игровых фактов**: HP людей и ботов,
   урон, смерть, респавн, КД, счёт, Оболочка, осколок, носильщик.
2. **Клиент** присылает только ввод и намерения:
   - `move` (позиция/поворот, 12–15 Гц);
   - `attack_intent {target, skill, cast_id}`;
   - `use_ability {skill, cast_id, target/direction}`;
   - `pickup/deliver` — намерение, сервер проверяет расстояние.
3. **Сервер** валидирует (существование, команда, дальность, КД, живость),
   считает урон, применяет и рассылает **снапшот**:
   - люди: позиция, HP, max_hp, alive, анимация;
   - боты: позиция, HP, alive, анимация;
   - Оболочка: alive, hp, позиция, фаза;
   - осколок: состояние, позиция, носильщик;
   - счёт, таймер, фаза матча.
4. **Клиент** интерполирует удалённые сущности, предсказывает только своего
   героя и корректируется сервером. HP и смерти — **никогда** не по локальному
   решению клиента.
5. **Позднее подключение**: при входе сервер отдаёт полный снапшот, а не
   ждёт следующего события.
6. **Тест**: два клиента (хост/гость), задержка 100–200 мс, потеря 5–10%,
   смерть/респавн, Оболочка, осколок, конец матча. Проверять **оба экрана**,
   а не только хост.

## 5. План миграции (по шагам)

1. **Снапшоты людей** — уже сделано: HP в `state` 12 Гц.
2. **Урон** — передавать фактический урон в `attack_intent`, сервер
   клампит по `attackDamage * 2.5`; убрать разницу 53 vs 44.
3. **AoE** — `cast_id` на каст, сервер принимает все цели одного каста.
4. **Боты** — сервер считает урон и HP; хост присылает только позиции и
   намерения атак. Убрать «HP бота растёт обратно».
5. **Оболочка/осколок** — `shell_state`/`crystal_state` от хоста или сервера,
   урон по Оболочке — интентом.
6. **Тест-матрица** — два клиента, оба экрана, логи `[HP]`, `[HIT]`, `[DMG]`,
   `[BOTHP]`, `attack_denied`.

## 6. Что уже исправлено в этой итерации

- HP людей в каждом `state`-пакете и применение на клиенте.
- Респавн из `state`, если пакет смерти/респавна потерялся.
- Миникарта: `remote_players` (союзники и второй игрок).
- Конец сетевого матча — только сервер, счёт — только серверный.
- Реген базы ×2 вместо ×6 (60 HP/с делали игрока бессмертным).
- Ограничение клиентского `stats` (не больше 300 HP/с).
- HP ботов: сервер принимает HP хоста в обе стороны.
- Урон ботов по хосту идёт через `attack_intent`.
- Отладочные логи `[HP]`, `[HIT]`, `[DMG]`, `[BOTHP]`, `[SHELL]` при
  `?profile=1` — чтобы больше не гадать.

## 7. Итерация 21.11: серверный HP ботов и Оболочки

Сделано:
- **HP ботов принадлежит серверу.** Хост присылает только позицию, поворот и
  анимацию; HP/max_hp в `bot_states` игнорируются. Урон по ботам идёт через
  `attack_intent` / `bot_damage`, лечение — через `heal` с отрицательной
  целью, реген считает сервер. Сервер рассылает HP и хосту, и гостю.
- **HP и состояние Оболочки принадлежит серверу.** Хост присылает
  `shell_state` (позиция/фаза/таймер), HP не присылает. Урон по Оболочке —
  `shell_attack`; сервер применяет, рассылает `shell_state` и
  `match_event: shell_destroyed`. Гость не спавнит свою Оболочку, а рисует
  серверную.
- **Протокол 2.** Новый клиент с новым сервером использует серверный HP; со
  старым сервером (протокол 0) работает по-старому. Это защищает от
  смешанной версии при поэтапном деплое.
- Локальный тест: `[DMG] source=-4 target=-2 amount=32` → `B:-2 938/1000`,
  `B:-4 945/1050`; HP меняется ровно на подтверждённый урон, снапшоты хоста
  его не откатывают.
- Серверный тест `TestShellStateAndDamageAreServerOwned` проходит.

Осталось:
- **Осколок** — перенесён на сервер (см. раздел 8).
- Атаки Оболочки по игрокам (PvE) остаются локальными на хосте.
- AI/движение ботов остаются на хосте (доверенный симулятор), сервер владеет
  их HP/уроном/смертью/регеном.

Тесты нового сервера (21.11, после рестарта ПК):
- `go test ./...` — все тесты проходят.
- `TestWebSocketBotSyncAndServerValidation` двумя WebSocket-клиентами:
  - welcome отдаёт `protocol: 2`;
  - урон гостя по боту применяется сервером;
  - снапшот хоста с полным HP **не поднимает** серверный HP;
  - лечение бота хостом применяется сервером;
  - `shell_state` создаёт Оболочку на 1000 HP;
  - урон по Оболочке применяется сервером, снапшот хоста с HP 100
    игнорируется;
  - смерть Оболочки и `match_event: shell_destroyed` приходят от сервера;
  - матч завершается серверным счётом.
- Локальный браузерный прогон (до рестарта): `B:-2 938/1000`,
  `B:-4 945/1050` — HP ботов меняется ровно на подтверждённый урон.

## 8. Итерация 21.11: серверный осколок

Сделано:
- Сервер хранит состояние осколка: `none / ground / carried`, позицию и
  `carrier_id`.
- Смерть Оболочки на сервере создаёт осколок на её позиции и рассылает
  `crystal_state`.
- Подбор: клиент шлёт `crystal_pickup` (для бота — `source_id < 0`), сервер
  проверяет дистанцию 2.5 и делает носильщиком.
- Доставка: `crystal_deliver`; сервер проверяет, что носильщик — источник,
  и что он у своей базы; начисляет счёт, рассылает `crystal_state` +
  `match_score`, при 3 осколках завершает матч.
- Смерть/выход носильщика: сервер роняет осколок в его позиции; клиенты
  видят `ground`.
- Гость не спавнит свой осколок; рисует серверный. Хост-боты подбирают и
  несут через те же интенты.
- Протокол **3**; старый сервер (2) → клиент работает по-старому с локальным
  осколком.

Тест `TestWebSocketBotSyncAndServerValidation` двумя клиентами:
- смерть Оболочки → `crystal_state: ground`;
- `crystal_pickup` → `carried` с `carrier_id`;
- доставка у базы → `none` и счёт **0:1**;
- счёт/конец матча — серверные.

## 9. Полный аудит сетевого кода (21.11)

Проведён разбор трёх слоёв: сервер, сетевой клиент, экономика. Найдено и
исправлено:

Критичное:
1. `state` рассылался без `class/team` (Go-поля без `omitempty` → 0/0), а
   клиент перезаписывал ими удалённых игроков на каждом пакете: у хоста гость
   становился союзником. Сервер шлёт реальные `class/team`; клиент берёт их
   только из roster-сообщений.
2. Подтверждённый урон по ботам вызывал `apply_network_damage(amount, show)`
   при сигнатуре с одним аргументом → ошибка скрипта: не было цифр урона,
   kill feed и золота. Сигнатура и вызовы выровнены.
3. Сетевой урон шёл без `HERO_OUTGOING_DAMAGE_MULTIPLIER` (×2) → весь урон и
   цифры вдвое меньше офлайна. Интенты героя и Оболочки несут итоговый урон.
4. Смерть носильщика-человека не роняла осколок (только боты) → осколок
   застревал в `carried`. Сервер роняет при смерти любого носильщика; добавлен
   тест `TestHumanCarrierDropsCrystalOnDeath`.
5. Смерть бота от хоста (`bot_states alive=false`) игнорировалась. Теперь
   сервер принимает её и роняет осколок.
6. `crystal_state: carried` при отсутствии ноды: `spawn_crystal` сбрасывал
   состояние в `ground` и снимал носильщика. Порядок исправлен.
7. `match_event shard_delivered` давал очко без осколка (чит). Теперь идёт
   через ту же проверку, что `crystal_deliver` (осколок несёт именно он, он у
   своей базы), и потребляет осколок.
8. `shell_destroyed` от гостя мог отключить Оболочку и осколки. Принимается
   только от хоста.
9. Оболочка воскресала от запоздавшего `alive=true` при живом осколке; смерть
   Оболочки перезаписывала уже носимый осколок. Добавлены guard'ы и
   `shellDiedAt` (2 с).
10. Респавн живым в любой точке с полным HP; лечение мёртвым без лимита;
    `stats` с `max_hp/attack_damage` до 100000. Теперь: респавн только после
    смерти и 4 с, лечение только живым с бюджетом 4 пакета/с и капом 400,
    stats клампятся к 1.6×HP и 2.5×урона класса.
11. Золото: +50 за убийство, +100 за доставку и +100 за Оболочку начисляются
    по серверным событиям (`death.source_id`, `shard_delivered`,
    `shell_destroyed.team/source_id`). Крит передаётся флагом и рисуется
    красным. Для protocol 3 оставлены fallback'и (урон/переход осколка), чтобы
    новый клиент работал со старым сервером.

Среднее/низкое, исправлено:
- осколок на земле возвращается к алтарю через 30 с (сервер) — матч не встаёт;
- радиус подбора выровнен: 3.2 у клиента и сервера;
- у гостя после смерти Оболочки оставался невидимый коллайдер — вызывается
  `deactivate()`;
- пропавший `death` больше не оставляет труп с полным HP: смерть чинится по
  `state` (`alive=false`);
- `server_protocol` сбрасывается при переподключении;
- sudden death получает таймер 2 минуты;
- убраны чтения полей клиента/комнаты после `Unlock` (data race);
- при выходе мёртвого игрока бот наследует его HP/смерть, а не полный HP.

Проверено локальным прогоном (свой сервер, два нативных клиента):
- комната 2/6, команды разные, старт с ботами;
- счёт на обоих экранах совпадает: 0:0 → 0:1 → 1:1 → 1:2;
- золото растёт (201 → 451 → 607), в том числе за доставки;
- kill feed «Darones × Darones» виден на обоих экранах;
- смерть и «Возрождение 7» работают.

  сервере;
- валидация скиллов по классу и кулдауны мультитаргета;

## 10. Итерация 21.11: Оболочка по гостям, скиллы, сессии, золото

Доделано то, что раньше было «вне прохода».

Оболочка и база:
- хост выбирает цель Оболочки и среди гостей (`RemotePlayer`), бьёт интентом
  `world_damage`; сервер проверяет живую Оболочку, дистанцию 15 м, щит базы и
  применяет урон к авторитетному HP. Гость видит `damage` и получает вспышку.
- `shell_bolt` — событие для гостя: сервер ретранслирует точку удара, гость
  рисует молнию/кольцо (сам он Оболочку не симулирует).
- щит базы теперь проверяется **на сервере** (`underBaseShield`, радиус 5 м):
  `attack_intent` и `world_damage` по цели под щитом отклоняются.

Скиллы:
- серверная таблица «класс → допустимые скиллы»: воин — `auto`,
  `shadow_assassin`, `fear_ult`; маг — `auto`, `root`, `ult_lightning_storm`;
  арбалетчица — `auto`, `stun`, `stun_shot`, `fairy_ult`, `crit_shot`. Чужие
  скиллы отклоняются (`invalid_skill`).
- мультитаргет: вместо «350 мс без кулдауна» — окно каста 400 мс с дедупом
  целей; каждая цель каста получает урон один раз, повторный каст — по КД.

Сессии и экономика:
- у игрока появился `session_token`; `/register` возвращает токен, первый
  `/profile` нового клиента его забирает (`X-Claim-Session`), дальше все
  запросы идут с `X-Session-Token`. Старые клиенты без токена продолжают
  работать в режиме миграции, пока аккаунт не займёт новый клиент.
- `/match_reward`: обязательны токен и `room_id`; награда выдаётся ровно один
  раз на завершённый матч (атомарная отметка `matches.rewarded`), потолок — 10
  шаров вместо 100000.
- золото матча теперь ведёт сервер: монеты (`coin_pickup`, лимит 6/с),
  +50 за убийство, +100 команде за осколок и Оболочку. Покупка — интент
  `buy_item`: сервер проверяет цену (таблица 10 предметов), наличие золота,
  близость к магазину и отсутствие повторной покупки, затем присылает
  `shop_purchase`; клиент применяет эффект только после подтверждения.
  Старый сервер (protocol 3) — прежний локальный магазин.
- результаты: таблица и MVP считаются по `heroes` + `remote_players`, у
  удалённых людей и ботов ведутся убийства/смерти/урон/осколки/Оболочки.
  Гость больше не получает MVP «по умолчанию».
- стан Оболочки и скиллов теперь доходит до гостя: сервер кладёт `stun` в
  пакет `damage` (Оболочка — 1 с, `fear_ult`/`stun_shot` — 1.5 с), клиент
  цели применяет его к своему герою; «Оберег от сглаза» режет стан на 20%.
- статы предметов считает сервер, а не клиент: `maxHP` и урон выводятся из
  класса и купленных предметов (амулет +150 HP, перчатка +25 урона), броня
  Титана даёт −15% входящего урона, клык вампира — 15% вампиризма, талисман
  возрождения — +10 HP/с регена, песочные часы — −15% КД, метка ловкости —
  +20% скорости автоатаки, оберег — −20% стана. Пакет `stats` больше не
  задаёт боевые статы и не лечит: HP и урон полностью серверные.

Проверено: `go test ./...` (включая новые тесты золота/покупок и смерти
носильщика), headless-клиент против локального сервера — без ошибок скриптов,
комната и матч стартуют.

## 11. Три живых боя и второй аудит (21.11)

Прогнаны три матча двумя нативными клиентами на публичном сервере, по 4
минуты, за разные классы:

1. Воин (Свет) — Маг (Тьма): счёт 1:0, золото 467, ошибок скриптов нет.
2. Арбалетчица (хост) — Воин (гость): счёт 0:1, золото 108, ошибок нет.
3. Маг (Свет) — Арбалетчица (Тьма): счёт 0:1, маг полный HP, арбалетчица
   погибла у фонтана, ошибок нет.

Найдено в боях/аудите и исправлено:

- **Критично: награда за матч не начислялась вообще.** `game._exit_tree`
  отключает сеть и обнуляет `room_id` до `ResultsScreen._ready`, а
  `grant_match_reward` требовал `room_id > 0`. Теперь `end_match` кладёт
  `last_match_room` в мета-данные дерева, награда идёт по нему; офлайн-матчи
  начисляют осколки локально. Рекламное удвоение — отдельный идемпотентный
  `bonus`-запрос (колонка `matches.rewarded_bonus`). Бонус за уровень больше
  не теряется в `pending_level_shards`.
- **Критично: прелоадер эффектов не работал.** `vfx_preloader.gd` вызывал
  `look_at` у камеры до добавления в дерево — ошибка обрывала прогрев, и
  шейдеры компилировались в бою. Камера добавляется первой. Это убирает
  фризы первого боя (в логах были 0.6–0.9 с).
- **Фриз на входе в бой:** `bake_navigation_mesh(false)` пёк навмеш в главном
  потоке. Переведено на фоновый бейк (`true`).
- **Мобильный HUD на 16:9:** `UiLayout` масштабировал только по высоте
  (844×390 дизайн), из-за чего скиллы 2–3, счёт/таймер/золото и кнопки лобби
  уходили за экран. Масштаб — `min(viewport.x/844, viewport.y/390)`.
- **Удар Оболочки по хосту** применялся только локально и откатывался
  синхронизацией. Теперь хост шлёт `world_damage` на себя, HP и стан — серверные.
- **PvP-урон по удалённым игрокам** шёл без ×2 и без крита
  (`RemotePlayer.take_damage`). Множитель и `is_crit` добавлены.
- **Смерти удалённых игроков** не считались (пакет `death` приходил после
  смертельного урона). Счётчик перенесён в `apply_network_death` (идемпотентно).
- **Статистика ботов у гостя** была нулевой: все кредиты требовали
  `network_host`. Добавлен `_network_combatant` (боты хоста или `RemotePlayer`).
- **Двойное лечение** на клиенте лекаря: серверное эхо применялось повторно.
  Эхо с `source_id == local` для чужой цели пропускается.
- **Коллизия удалённой Оболочки** после первого цикла не включалась обратно
  (`deactivate` → нужен `activate`). Исправлено.
- **Магазин:** повторные клики и потерянный ответ. Добавлены `pending`-предмет
  и таймаут 3 с; эффект применяется только при успешном `apply_shop_item`.
- **Молния** больше не создаёт по мешу и материалу на сегмент: один набор
  мешей/материалов на удар (было ~27 материалов, стало 2).

Осталось (не критично, вне этого прохода): VFX-сцены на каждую автоатаку,
перерисовка HUD каждый кадр, кнопка паузы на мобиле, экран результатов без
данных, гонка повторного старта матча.

## 13. Пятый проход: Оболочка, хил, результаты, хостинг (21.11)

Жалобы после сборки `145211` и что сделано:

- **Оболочка исчезала сразу после спавна / больше не появлялась.**
  Причин было две. Сервер отвергал новый спавн, пока на поле лежал осколок
  от прошлой Оболочки (`shardActive`), и присылал `alive=false` — хост прятал
  только что созданную Оболочку. А если сервер отказывал, клиент оставался в
  фазе `active` с мёртвой Оболочкой и больше не спавнил её до конца матча.
  Исправлено: сервер больше не блокирует новый спавн осколком (осколок и
  Оболочка могут существовать одновременно, дубликат осколка не создаётся);
  у переносимого осколка появился таймаут 45 с (падал у носителя, затем
  обычные 30 с на земле); хост при отказе сервера сбрасывает цикл и повторяет
  через 5 с; в `_process` есть страховка от застрявшей фазы `active`.
- **Хил срабатывал медленно и не показывал +N.** Сервер применял лечение к
  цели, но рассылал эхо всем, кроме самого лекаря (`roomClientsLocked(room,
  client.id)`). Маг лечил себя, но его HP рос только на следующем `sync` раз
  в секунду, и цифры не было. Теперь эхо уходит всем, включая лекаря, и в нём
  реально применённое количество (не больше недостающего HP). Клиент больше
  не отбрасывает эхо для ботов хоста: их лечение тоже применяется только
  сервером.
- **Серый экран после боя.** `results_screen.gd` не компилировался:
  `var character_key := CHARACTER_KEYS[selected_class]` и `var leveled_up := ...`
  не выводили тип, Godot 4.7 падал с Parse Error, сцена открывалась пустым
  серым `Control`. Типы проставлены. Проверено живым матчем с ускоренным
  таймером: оба клиента доходят до экрана результатов, кнопки и награды
  работают.
- **Ники-кракозябры.** В серверных fallback-именах (`botFromClient`,
  `joinMatchmaking`, `startRoomLocked`) лежали байты cp1251→UTF-8. Заменены на
  «Игрок N». Дефолты в `loading_screen.gd` тоже починены.
- **GitHub Pages очень медленно отдаёт игру.** 45 МБ PCK качались с
  ~44 КБ/с (25 с — 1 МБ). Игра теперь раздаётся тем же сервером RelaxDev по
  `/game/` (33 мс отклик), с gzip для wasm (39 МБ → ~10 МБ) и кэшем крупных
  файлов на диске контейнера. GitHub Pages остаётся запасным адресом.

Проверки:
- `go test ./...` — проходит, добавлены тесты на спавн Оболочки при активном
  осколке, таймаут переносимого осколка, эхо лечения лекарю и раздачу
  `/game/`.
- Живой матч двух клиентов с таймером 30 с: оба дошли до результатов,
  ошибок скриптов нет.


Второй серверный аудит (античит):- `normalizeSkill` приводит имя к нижнему регистру — `"Auto"`/`"AUTO"` больше
  не обходят КД отдельными ключами.
- серверные КД взяты из клиентской таблицы `CLASS_DATA`: автоатака 0.6/1.0/0.75
  с, `shadow_assassin` 8 с, `fear_ult` 37.5 с, `root` 10 с, `stun` 12 с,
  `crit_shot` 15 с, `fairy_ult` 36 с, шторм 42 с (но тики 1/с в окне 6 с с
  дедупом цели).
- убран пол урона 400: пакет принимается не больше `base × 2 × 2.6` (крит),
  иначе сервер считает сам; `crit_shot` больше нельзя слать каждые 0.5 с.
- `world_damage` ограничен: не чаще одного удара по одной цели в 2 с, радиус
  15 м от живой Оболочки, щит базы.
- лечение: кап 300 за пакет, очередь 8 с восстановлением 2/с, self-heal мага
  снова работает через сервер (раньше откатывался синхронизацией).
- стан снижается только на клиенте (раньше и сервер, и клиент применяли
  «Оберег» — 1.5 с превращались в 0.96); добавлены станы `shadow_assassin`
  1 с и `root` 2 с.
- щит базы: серверные константы выровнены с клиентом (28.0 / 4.9).
- респавн клампится ареной ±52/±37 и требует 6 с после смерти.
- `/match_reward`: `FOR UPDATE` без `SKIP LOCKED` + индекс `(room_id, player_id)`
  — два параллельных запроса не ловят deadlock на дублях.
- клиент больше не начисляет золото локально на protocol 4: +50/+100 приходят
  только серверным `gold` (раньше кошелёк опережал сервер и покупки отклонялись).

## 12. Полировка и производительность (21.11, третий проход)

Сделано:
- **Пул VFX попаданий**: сцены эффектов больше не создаются/удаляются на каждый
  удар, а переиспользуются (до 4 на сцену) с перезапуском партиклов, анимации и
  звука. Первый удар создаёт, дальше — повторное использование.
- **Пул цифр урона/лечения**: 32 Label3D переиспользуются, твин перезапускается.
- **HUD**: шейдер КД обновляется только при изменении прогресса (было каждый
  кадр), пульс туториала перестраивает стили шагами, а не 60 раз в секунду.
- **Кнопка паузы** создаётся на всех платформах и видна в бою.
- **Туториал** называет кнопку по номеру: «Нажми мигающую кнопку 1 справа
  (Теневой рывок)» — совпадает с подписью «1» на кнопке.
- **Экран результатов без данных** не начисляет награды и XP.
- **Гонка старта матча**: `state = "starting"` + флаг, второй тап игнорируется.
- **Диалог лицензий** вписан в 960×540 и мобильный экран.
- **Превью героя в лобби** рендерится только когда меню открыто
  (`UPDATE_WHEN_VISIBLE`).
- **Монеты**: общий меш и материал, без создания на каждый спавн.
- **Видимость врагов**: 5 Гц вместо 8 Гц (меньше рейкастов).
- **Смена хоста**: сервер гасит Оболочку и рассылает `shell_state`, новый хост
  удаляет гостевую копию и спавнит свою через ~5 с.
- **Ничья в sudden death** больше не отдаётся всегда команде 0.
- **Награда за матч** ограничена сервером: победа — максимум 5, поражение — 3.
- Кракозябры в `loading_screen.gd` и битый ключ в `project.godot` убраны.
