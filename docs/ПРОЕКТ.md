Документ для продолжения работы. Обновлён 12.11.2026.

---

## 1. Обзор

- **Клиент:** Godot 4.7.2, рендер `forward_plus`, 3D, три героя (Воин, Маг, Лучница).
- **Режим:** PvP 1v1 / 2v2 с добивкой ботами, сбор осколков на арене.
- **Сервер:** Go + PostgreSQL, хостинг RelaxDev.
- **Точка входа:** `res://scenes/Lobby.tscn` (лобби → матч).
- **Платформы:** Windows (self-hosted), планируется веб для Яндекс Игр / VK / OK.

## 2. Как запустить

### Клиент

```powershell
cd C:\myGames3D\three-skies
godot --path .                      # обычный запуск (лобби)
godot --headless --path . res://scenes/Main.tscn --quit-after 4   # быстрый прогон на ошибки
```

### Сборка PCK (без exe)

```powershell
godot --headless --path . --export-pack "Windows Desktop" build\windows\ThreeSkies.pck
```

Текущий размер PCK: **37.9 МБ**. Лимит Яндекс Игр — 100 МБ распакованного.

### Сервер

```powershell
cd server
go run .            # локально
```

Деплой — через RelaxDev (push в `main`). После правок Go **обязателен редеплой**, иначе клиент работает со старым билдом.

## 4. Генерация карты — как это работает на самом деле

Это место, где легко потерять время, поэтому подробно.

### Главная ловушка

В `scenes/Main.tscn` арена **уже запечена**: узлы `Stage`, `Island` (Floor, Cliffs, стены, коллизии), `Altar`, `Ruins`, `Bases`, а также старые `Decor` и `Bushes`.

А в `game.gd` вызов стоит так:

```gdscript
if get_node_or_null("Arena") == null:
    ArenaKit.build(arena)
```

Узел `Arena` в сцене есть → **`ArenaKit.build()` в матче не вызывается никогда**.
Всё, что лежит в `build()` и вызываемых из него функциях, в игре не работает.

### Что работает в матче

`game.gd` вызывает только:

```gdscript
ArenaKit.ensure_perimeter_ridge(arena_root)
ArenaKit.ensure_arena_features(arena_root)
```

`ensure_arena_features()` делает:
1. `_ensure_light_floor` — перекрашивает пол;
2. `_ensure_visible_boundary_walls` — при необходимости добавляет стены забора;
3. `_ensure_fence_collision` — коллизии забора;
4. **`_rebuild_decor`** — удаляет запечённые `Decor`/`Bushes` и строит декор заново из кода;
5. `_ensure_decor_collisions` — коллизии камней и деревьев;
6. `_ensure_navigation_region` — навигационная сетка.

**Вывод: править раскладку нужно в `arena_kit.gd` (`_add_decor`, `add_bushes`), а не в `Main.tscn`.**

### Геометрия арены

| Параметр | Значение |
|---|---|
| Забор (игровая граница) | `HALF_X = 27`, `HALF_Z = 19.5` |
| Пол (запечён) | 52.5 × 37.5 |
| Границы тумана и клампов | `ARENA_SAFE_HALF_X = 30`, `ARENA_SAFE_HALF_Z = 22` |

Раньше туман был 104 × 74 — вдвое больше арены, из-за этого карта «казалась огромной». Теперь 60 × 44, чуть больше забора и обрез.

### Раскладка декора (равномерная)

| Объект | Кол-во | Радиус (доля от арены) | Шаг |
|---|---:|---|---|
| Деревья | 12 | 0.90–0.93, по кромке | 30° |
| Камни | 9 | 0.58 ± 0.13 | 40° |
| Кристаллы | 6 | 0.44 ± 0.10 | 60° |
| Кусты | 5 зон | 0.52 | 72° |

Центр с алтарём и подходы к базам остаются свободными.

### Функции-помощники

- `_shape_point(ang, scale)` — точка на эллипсе арены с «дрожанием» кромки.
- `_is_inside(x, z)` — попадание внутрь острова.
- `_place_inside(pos)` — подтягивает точку внутрь, если вышла за край.
- `_add_rock(parent, pos, scale, mat)`, `_add_tree(...)`, `_add_glowing_tree(...)`, `_add_crystal_cluster(parent, pos, color, scale)`.

Внимание: у `_add_crystal_cluster` порядок аргументов **`(родитель, позиция, цвет, масштаб)`** — если перепутать, скрипт не скомпилируется целиком и арена останется пустой.

## 5. Сервер

**URL:** `https://three-skies-server.relaxdev.ru`
**WebSocket:** `wss://three-skies-server.relaxdev.ru/ws`

### Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | `{"status":"ok","database":"ok"}` |
| GET | `/rules` | Правила матча (проверка, что задеплоен новый билд) |
| WS | `/ws` | Игровой сокет |
| POST | `/register` | Регистрация/вход |
| POST | `/profile` | Профиль: осколки, крылья, оружие, ник |
| POST | `/rename` | Смена ника |
| POST | `/report` | Результат матча |
| POST | `/buy_wing` | Покупка крыльев |
| POST | `/buy_weapon` | Покупка оружия |
| POST | `/match_reward` | Награда за матч |

### Правила матча (в `ws.go`)

- Осколков до победы: **3**
- Добивка ботами: **30 секунд**
- Длина матча: **600 секунд**

Проверка после деплоя:

```
GET /rules → {"crystals_to_win":3,"bot_fill_seconds":30,"match_length_seconds":600}
```

Если возвращает 404 — сервер старый, редеплой не прошёл.

### Ограничения сервера

- Покупки валидируются на сервере: `buy_weapon` сейчас принимает **только `weapon_id = 1`**, `buy_wing` — `1..4`.
- Значит для лука (`weapon_id = 2`) нужна правка Go + редеплой.

## 7. Крылья — состояние

### Белые (готовы как модель)

- Файл: `assets/wings/angel_wings_animated.glb`, **0.98 МБ**, **6 292 трис**.
- Геометрия: исходные два квада (4 трис каждый) разрезаны по альфе, добавлена толщина 11 мм и изгиб 21 см.
- Риг: 3 кости на крыло (`WingL_01..03`, `WingR_01..03`).
- Анимация: `Flap`, 5 секунд, кончики ~4° — «дыхание», без взмахов.
- Проверено на Лучнице: сидят правильно, крепление через `Spine02`.

**Не подключены в игру.**

### Как работает привязка (hero.gd)

```
Spine02 (кость) → BoneAttachment3D → WingAttachment → модель крыльев
```

- Смещение: `(0, 0, -0.32)`, поворот модели `(0, 18, 10)`.
- `update_wings()` сейчас грузит **один и тот же файл для любого `wing_id`** и делает `wing_anim_player.stop()`.
- Нужно: карта `wing_id → модель` и проигрывание анимации вместо `stop()`.

### Демонические (сломаны)

- Файл: `assets/wings/low_poly_demon_wings_animated.glb`, 3.12 МБ, 1 556 трис, 42 кости.
- **Масштаб 452 юнита** в ширину, origin сдвинут на z = 144…348 → в игре это гигантская модель.
- Анимация: 374 кадра (~15 с), играет рывками.
- `hero.gd` её принудительно останавливает.
- Нужно: нормализовать масштаб до ~1.8 м, перенести origin между лопатками, вырезать один цикл, сжать текстуры до 512.

### Решения по крыльям

- Родные крылья Лучницы **не вырезаем** — накрываем нашими (меш Лучницы это «трисорный суп» из 10 058 кусков, резать рискованно).
- Вшитый лук Лучницы тоже **не вырезаем** — легендарный лук сажаем в ту же руку, он крупнее и перекрывает.
- Золотой резной орнамент кодом не получается (4 попытки) — согласована замена: золотые крылья через шейдер, без филиграни.
