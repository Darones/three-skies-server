# QA: реклама x2 и interstitial после итогов (26.11.2026)

Жалоба: смотрел rewarded-рекламу на x2 — x2 не засчитали, и следом показали
interstitial. Ничего не коммичено и не задеплоено.

## Причина

Виновата не одна строка, а цепочка из трёх независимых дефектов. Первые два
воспроизводят жалобу целиком.

1. **Rewarded-видео не укладывалось в таймаут показа.**
   `vk_adapter._call_ad_bridge()` имеет бюджет 20 с по умолчанию, и именно с ним
   вызывался `VKWebAppShowNativeAds` для `ad_format: reward`
   (было: `vk_adapter.gd:165`). Промис VK по документации разрешается **после
   закрытия рекламы**, то есть его время = загрузка + весь ролик (reward-видео
   у VK 15–30 с). Ролик в 21–30 с всегда заканчивался `error=timeout`:
   адаптер возвращал `false`, x2 не начислялся, хотя игрок рекламу досмотрел.
   Поздний ответ VK отбрасывался стражем `seq`, так что награда терялась
   безвозвратно.
2. **После неудачной/незавершённой попытки разрешался interstitial.**
   `AdManager.rewarded_watched_this_results` выставлялся только при успехе
   (`AdManager.gd:22`), а `can_show_interstitial_after_results()` смотрел только
   на него. Итог: игрок посмотрел рекламу (для нас — «неудачную»), нажал
   «В лобби» и получил **второй рекламный экран**.
3. **Бонус x2 мог уйти на сервер раньше базовой награды.**
   `results_screen._on_rewarded_ad_completed()` сразу отправлял `bonus=true`.
   Сервер принимает бонус только по строке матча с `rewarded = TRUE`
   (`matchRewardBonusClaimQuery`). Если базовая награда ещё летела или упала
   с сетевой ошибкой, бонус получал `409 Reward already claimed`, при этом UI
   уже показывал «×2 НАГРАДЫ УДВОЕНЫ» и удваивал числа. Игрок видел успех,
   сервер не платил. Запись оставалась в outbox `MetaProgression` до
   следующего профиля — то есть «x2 не засчитали» до перезахода.
4. Побочно (сервер): у строк, награждённых до появления `reward_shards`,
   бонус падал в `amount` из запроса, а клиент присылает **уже удвоенную**
   сумму → выплата 3x. Плюс `Reward already claimed` отдавался и тогда, когда
   строки матча ещё нет в БД: клиент считает такую ошибку терминальной и
   выбрасывает базовую награду навсегда.

## Что изменено

### `scripts/platform/vk_adapter.gd`
- `34–35`: `REWARDED_SHOW_TIMEOUT = 120.0`, `INTERSTITIAL_SHOW_TIMEOUT = 90.0`.
- `173`, `205`: показ reward/interstitial ждёт столько, сколько длится реклама
  (4× максимального ролика VK + загрузка).
- `215–243`: `_ad_result_flag()` читает `result` (а также `success`/голый bool)
  и разбирает строки явно: `"false"` больше не становится truthy. Отсутствующий
  или `false` результат по-прежнему значит «награды нет» — тестовую рекламу
  никто не «обманывает».
- `188–191`: «промис выполнился без `result=true`» помечается как
  `not_completed`, а не `no_fill` (в логах было не отличить «нет фила» от
  «закрыл раньше времени»).

### `scripts/AdManager.gd`
- `17`, `23`, `29`: новый флаг `rewarded_attempted_this_results`; сбрасывается в
  `begin_results()`, ставится и при успехе, и при попытке.
- `32–38`: `can_show_interstitial_after_results()` возвращает `false`, если
  rewarded **смотрели или пытались смотреть** в этом же results.
- `82–85`: флаг ставится **до** вызова адаптера, поэтому таймаут/отмена/`no_fill`
  тоже закрывают interstitial.

### `scripts/results_screen.gd`
- `38–45`: состояние x2 — `reward_room`, `base_reward_settled`,
  `base_reward_ok`, `pending_bonus`.
- `233–238`: экран подписывается на `NetworkClient.match_reward_settled`
  до отправки базовой награды.
- `861–880`: при успехе rewarded бонус **не отправляется сразу**: он ждёт
  подтверждения базы. Если база уже подтверждена — уходит немедленно.
- `895–907` `_send_ad_bonus()`: единственная точка отправки бонуса, сумма —
  ровно удвоенный итог (`final_shards`/`final_xp` удваиваются один раз).
- `909–935` `_on_results_reward_settled()`: база подтверждена → бонус; база
  упала → бонус всё равно ставится в очередь (`MetaProgression` хранит его
  **после** базы), ответ на сам бонус только логируется.
- `938–944` + `784`, `799`: при выходе из итогов незавершённый бонус
  досылается в outbox — уход со экрана его не теряет.
- Локально ничего не начисляется дважды: для серверного матча по-прежнему нет
  `add_character_xp`, дельта статистики считается один раз.

### `server/main.go` (только ad/reward-часть)
- `2007–2040`: бонус — проверка `RowsAffected` у пометки `rewarded_bonus`;

  `Reward already claimed` (реально уже выплачено).
- `2108–2114`: лог каждой выплаты — `match reward paid …` /
  `match x2 paid …` с shards/xp/character/level_shards/new_shards.

### `server/ads.go`
- `14–24`: константы ответов, `baseRewardCap()` (5 победа / 3 поражение).
- `40–52`: `bonusPayoutShards()` — бонус = сохранённая база (ровно x2);

Сценарии нового probe (`tools/results_ad_x2_probe.gd`):
- (a) rewarded success → база не подтверждена → бонус ждёт; база подтверждена →
  один бонус с удвоенной суммой и тем же персонажем;
- (b) база не ответила/упала → x2 ставится в очередь и лежит в outbox **после**
  базы (порядок `_flush_pending_match_rewards`), сумма не теряется;
- (c) rewarded fail → нет x2, нет локальной выплаты, нет записи в outbox,
  `can_show_interstitial_after_results() == false`, `maybe_show_interstitial…`
  не вызывает адаптер (контроль: без попытки rewarded interstitial разрешён);
- (d) rewarded watched → interstitial запрещён;
- (e) второй клик (и двойной клик в одном кадре) не открывает вторую рекламу и
  не платит второй раз — ни на сервере, ни офлайн.

Probe не ходит на реальный сервер: `NetworkClient.api_base_url` переводится на
`http://127.0.0.1:9`, профиль/статистика бэкапятся и восстанавливаются.

## Риски и что осталось

- **iPhone/VK без reward-fill.** Если VK отдаёт по reward-слоту waterfall-рекламу
  без награды (`result=false`), x2 не начисляется — это правильно, чинить на
  клиенте нельзя. Теперь это видно в логах как `show reward … result=false
  error=not_completed` и `ms=` реальной длительности; второй рекламный экран
  после такой попытки больше не показывается.
- **Бюджет ожидания.** 120 с на reward: если бридж зависнет совсем, кнопка
  «Реклама…» провисит до 2 минут. Это осознанный обмен: старое значение было
  короче самого ролика и гарантированно теряло награду.
- **Окно между кликом и ответом базы.** Пока база не подтверждена, бонус живёт
  только в памяти экрана (не в `meta_save.cfg`); закрытие приложения в эти
  доли секунды потеряет x2. На практике база уходит в `_ready()` и её ответ
  приходит до конца рекламы, а выход с экрана досылает бонус.
- **Серверная миграция.** `reward_shards`/`reward_xp`/`reward_character` уже
  добавляются `ALTER TABLE IF NOT EXISTS`; отдельной миграции не нужно. Для
  старых строк бонус теперь ограничен базовым потолком (раньше мог быть 3x).
- Не менялись цены, награды и баланс: x2 по-прежнему ровно +100 % базовой
  выплаты, потолки 5/3 и `maxMatchReward` те же.
- `scripts/game.gd`, `hero.gd`, `warmup_flow.gd`, `loading_screen.gd`,
  `network_manager.gd`, `network_client.gd`, `MetaProgression.gd`,
  `remote_player.gd`, `server/ws.go`, UI-файлы не тронуты.
