# Редактор экранов и обучения

Дата: 25.11.2026.
Файл: `ui_editor.html` (корень) → копируется в `build/web` и `server/web`
скриптом `tools/web_export.py`. Фоны: `editor-bg/*.jpg`.

## Как открыть

- На проде после деплоя: `https://three-skies-server.relaxdev.ru/game/ui_editor.html`
- Локально (без деплоя):
  ```powershell
  cd C:\myGames3D\three-skies\server\web
  python -m http.server 8099
  ```
  затем `http://127.0.0.1:8099/ui_editor.html`.
- Живые экраны (лобби, инвентарь, магазин) работают и со статического сервера.
  Бой требует Go-сервер (WebSocket), иначе матч не стартует.

## С телефона

Можно, если телефон и компьютер в одной Wi-Fi сети.

1. На компьютере:
   ```powershell
   cd C:\myGames3D\three-skies\server\web
   python -m http.server 8099 --bind 0.0.0.0
   ```
2. Узнать IP компьютера: `ipconfig` → IPv4 (например, `192.168.1.102`).
3. На телефоне открыть `http://192.168.1.102:8099/ui_editor.html`.
4. Если не открывается — разрешить Python во входящих правилах
   брандмауэра Windows для частной сети (или использовать Tailscale-IP).
5. Повернуть телефон в landscape: сцена 844×390.
6. В «Экран» выбрать разрешение своего телефона: 844×390, 852×393,
   896×414, 915×412, 926×428 или «Свой размер».

Раскладка в браузере телефона хранится отдельно. Перенос:
«Скачать screens_layout.json» на телефоне → «Импорт JSON» на компьютере
(и наоборот). Импорт понимает и `screens_layout.json`, и `ui_layout.json`.

## Что внутри

Две группы страниц.

**Экраны:** загрузка (HTML), лобби, поиск матча, правила боя, бой/HUD,
пауза, итоги, инвентарь, магазин, пополнение осколков, настройки,
авторы и лицензии.

**Обучение по шагам (15):** 1. Добро пожаловать → 2. Тур по интерфейсу →
3. Дуэль 1v1 → 4. Шаг 1/3 пройден → 5. Фонтан и монеты → 6. Лавка →
7. Вступление к 2v2 → 8. Бой 2v2 → 9. Шаг 2/3 пройден → 10. Бой 3v3 →
11. Шаг 3/3 пройден → 12. Вступление к Оболочке → 13. Оболочка →
14. Осколок и база → 15. Победа обучения.

Всего 27 страниц.

## Как расставлять

- Выбери страницу слева. У каждой страницы свой набор плашек.
- Тяни плашку мышкой, тяни за углы для размера.
- Точные числа: поля **X / Y / W / H** справа. Это пиксели дизайн-пространства
  **844 × 390** — того же, в котором работает `scripts/ui_layout.gd`.
- Стрелки двигают на 1 px, Shift+стрелки — на 10 px.
- **Имя** и **Текст** — подпись плашки и текст, который потом пойдёт в игру
  (пока только в JSON).
- **+ плашка**, **Дублировать**, **Удалить** — только на статичных страницах.
- **По умолчанию** возвращает плашку к исходным координатам.
- Ctrl+Z / Ctrl+Shift+Z — отмена и повтор. Ctrl+← / Ctrl+→ — соседняя страница.

## Версия и экран

- **Версия → Мобильная**: живая игра открывается с `mobile=1`; базовое
  разрешение 960×540, дизайн-пространство 844×390.
- **Версия → Веб**: живая игра открывается без `mobile=1`; базовое 1280×720.
- Пресеты: телефоны 844×390, 915×412, 960×540, 780×360; веб 1280×720,
  1440×734, 1600×900, 1920×1080; плюс **Свой размер**.
- Позиции плашек пересчитываются по той же логике якорей, что в
  `ui_layout.gd::_apply`: левая/средняя/правая треть, верхняя/средняя/нижняя
  треть. Поэтому видно, куда плашка уедет на другом экране.

Важно: в веб-режиме лобби, инвентарь и магазин теперь отдают элементы
раскладки. Их позиции хранятся отдельно (`three_skies_ui_layout_web`)
и экспортируются в `ui_layout_web.json` в координатах **1280 × 720**.
Мобильная раскладка (`ui_layout.json`, 844 × 390) при этом не меняется.
Бой в веб-режиме пока не подключён — там по-прежнему нужна мобильная версия.

## Фон

- У каждой статичной страницы есть снимок экрана из `docs/qa-*.png`,
  сжатый в `editor-bg/*.jpg`.
- Снимки из прошлых сборок, поэтому старые плашки на фоне могут не совпадать
  с текущими координатами из кода. Ползунок **Фон** приглушает снимок,
  чтобы не мешал.
- **Свой фон…** — загрузить любой скриншот (сжимается в JPEG и хранится
  в localStorage).
- **Стандартный** — вернуть встроенный фон, **Без фона** — убрать совсем.

## Сохранение и файлы

Всё сохраняется в `localStorage` браузера, отдельно для каждого origin.
При открытии редактор подхватывает `ui_layout.json` рядом с собой, поэтому
экспорт живой раскладки полный даже без входа в лобби.

- **Скачать ui_layout.json** — живая раскладка для игры: лобби, бой,
  инвентарь, магазин; формат `version: 1`, `reference: 844×390`,
  `elements: { id: {x,y,w,h} }`. Кладётся в корень проекта и попадает в PCK.
- В веб-режиме эта же кнопка называется **Скачать ui_layout_web.json**
  и отдаёт веб-раскладку в координатах **1280×720**. Её тоже кладут
  в корень проекта; игра читает её на десктопе.
- **Скачать screens_layout.json** — все страницы и плашки обучения:
  формат `version: 2`, `pages: { page: { label, bg, plates } }`.
  Пока игра этот файл не читает — это заготовка для следующего этапа.
- **Скопировать JSON** — то же, что `screens_layout.json`, в буфер.

## Известные ограничения

- Живой бой на локальном статическом сервере не стартует: нет `/ws`.
  Проверять бой только на RelaxDev или на локальном Go-сервере с БД.
- Веб-бой (HUD) пока не подключён: `hud.gd` регистрирует бой только на
  мобильной раскладке. Веб-лобби, инвентарь и магазин работают.
- Инвентарь и магазин при открытии иногда отдают одинаковые X/Y для всех
  элементов (баг захвата геометрии в игре, не в редакторе). Если мешает —
  чинить отдельно в `ui_layout.gd`/`lobby.gd`, не в редакторе.
- Плашки обучения из `screens_layout.json` ещё не применяются в игре.
  Следующий этап: зарегистрировать `tutorial.dialog`, `tutorial.hint`,
  `tutorial.side`, `tutorial.skip`, `tutorial.press` в `UiLayout` и выбирать
  набор по стадии обучения. Без этого файл — только план раскладки.

## Файлы

- `ui_editor.html` — сам редактор (источник).
- `editor-bg/*.jpg` — фоны страниц.
- `server/web/ui_editor.html` и `server/web/editor-bg/` — локальная копия
  для проверки (обновляется `tools/web_export.py`).
- `tools/web_export.py` — копирует редактор и папку фонов в сборку.
- `scripts/ui_layout.gd` — рантайм-раскладка, читает `ui_layout.json`.
